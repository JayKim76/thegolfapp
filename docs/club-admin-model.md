# 운영 구조: 단일 모임 · 관리자 전담 관리

이 서비스는 "사용자 각자 쓰는 앱"이 아니다. 구조는 다음과 같다.

## 원칙

- 모임(Club)은 하나다. 백엔드 `Club` 모델의 단일 레코드가 전체 서비스의 소유자다.
- 계정은 관리자 계정 하나뿐이다 (`/api/auth/login`, 환경변수 `ADMIN_ID`/`ADMIN_PASSWORD`/`ADMIN_TOKEN`).
- 회원은 계정이 아니라 **관리 대상 레코드**다. 회원가입이 없고, 회원은 로그인하지 않는다.
  그래서 회원 이메일은 선택 항목이며, 앱에 회원가입 화면이 없다 (모바일 `SignUpScreen` 제거).
- 모든 쓰기(회원 등록/수정/삭제, 일정·조편성 저장, 골프장 추가, 라운드 저장, 모임 정보 수정)는
  관리자 토큰(`x-admin-token` 헤더)이 있어야 한다. 백엔드 `requireAdmin` 미들웨어가 강제한다.
  읽기는 토큰 없이 가능하다.

## 화면이 의미하는 것

- 모바일 홈 = 개인 기록이 아니라 **모임 대시보드**: 전체 회원 수, 평균 핸디캡, 최저 핸디캡 회원,
  등록 일정·기록된 스코어 수, 모임 구성(남/여/활동 회원).
- 모바일 하단 "관리" 탭(구 MY) = **모임 관리**: 모임명 수정, 회원 관리/등록, 일정·조편성,
  스코어 관리, 모임 통계로 가는 관리자 메뉴.
- 통계 화면 = 관리자가 회원을 골라 그 회원의 기록을 보는 화면 ("내 통계"가 아니다).
- 스코어 입력 = 관리자가 라운드에 참여한 회원 전원의 스코어를 입력·확정하는 흐름.

## 데이터

- `Club 1 ── N Member` (`Member.clubId`, 기본값 1). 시드는 클럽 1개를 만들고 전 회원을 거기에 넣는다.
- 모임 현황 집계는 `GET /api/club/stats` 한 곳에서 계산한다. 화면에 개인 통계를 하드코딩하지 않는다.

## 아직 개인 기준이 남아 있는 곳 (후속 과제)

- 라운드 저장은 백엔드가 아직 인메모리 목업이라 서버 재시작 시 사라진다. Prisma `Round` 모델로
  전환할 때 "관리자 입력 → 회원별 레코드" 형태로 맞출 것.
- 웹(루트) 앱은 목업 데이터 기반 프로토타입이라 대시보드 수치도 목업에서 계산한다.
  실연동 시 `/api/club/stats`를 그대로 쓰면 된다.
