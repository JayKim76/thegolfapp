# thegolfapp 서버 세팅

백엔드를 "개발자 PC에서 잠깐 띄우는 것"이 아니라 "항상 켜져 있는 서버"로 만드는 절차다.
레포에 함께 들어 있는 바로 쓰는 파일:

| 파일 | 용도 |
|---|---|
| `backend/ecosystem.config.js` | pm2 실행 설정 (Windows/Linux 공통, 권장) |
| `deploy/thegolfapp.service` | Linux systemd 유닛 예시 |
| `fix_firewall.ps1` | Windows 방화벽에서 3000 포트 열기 (레포 루트) |
| `backend/.env.example` | 환경변수 템플릿 |

## 1. 환경변수 전체 목록

`backend/.env` 하나만 관리하면 된다.

| 변수 | 필수 | 기본값 | 설명 |
|---|---|---|---|
| `DATABASE_URL` | 예 | - | `file:./dev.db` 고정 권장. 경로는 prisma 폴더 기준 |
| `PORT` | 아니오 | 3000 | 서버 포트 |
| `ADMIN_ID` | 아니오 | admin | 관리자 로그인 ID (계정은 이 하나뿐) |
| `ADMIN_PASSWORD` | **실사용 시 필수** | 1234 (개발용) | 관리자 비밀번호. 기본값 그대로 두지 말 것 |
| `ADMIN_TOKEN` | **실사용 시 필수** | dev-admin-token | 로그인 후 발급되는 토큰 값. 길고 랜덤하게. 바꾸면 기존 로그인 세션은 전부 풀린다 |
| `GEMINI_API_KEY` | OCR 쓸 때만 | 없음 | 없으면 OCR만 503 안내. 앱이 아니라 서버에만 둔다 |
| `GEMINI_OCR_MODEL` | 아니오 | gemini-2.5-flash | OCR 모델 교체 시 |
| `GEMINI_API_BASE` | 아니오 | 구글 기본 주소 | 테스트용 스텁 등 특수 경우만 |

## 2. 상시 실행 (pm2, 권장)

```bash
npm install -g pm2
cd thegolfapp/backend
npm install
npx prisma migrate deploy
npm run build            # dist/ 생성
pm2 start ecosystem.config.js
pm2 save                 # 재부팅 복원용 상태 저장
```

- 상태 확인: `pm2 status`, 로그: `pm2 logs thegolfapp`, 재시작: `pm2 restart thegolfapp`
- Windows에서 부팅 시 자동 시작까지 하려면 `pm2-startup` 계열 도구나 작업 스케줄러에 `pm2 resurrect`를 등록한다.
- 개발 실행(`npm run dev`, ts-node)으로도 동작은 하지만, 운영은 빌드된 `node dist/app.js` 기준이다 (ecosystem.config.js가 그 경로를 본다).

## 3. 상시 실행 (Linux systemd 대안)

```bash
sudo cp deploy/thegolfapp.service /etc/systemd/system/
# 유닛 파일 안의 경로(/opt/thegolfapp)와 실행 사용자를 실제 값으로 고친 뒤
sudo systemctl daemon-reload
sudo systemctl enable --now thegolfapp
journalctl -u thegolfapp -f    # 로그
```

## 4. 네트워크 열기

### 같은 네트워크(집/사무실 공유기)에서만 쓸 때

1. 서버 PC의 내부 IP를 고정한다 (공유기 설정에서 DHCP 예약 또는 PC에 고정 IP).
   IP가 바뀌면 앱이 못 붙는다. 앱의 `API_BASE`와 같은 값이어야 한다.
2. Windows 서버면 방화벽을 연다: 레포 루트의 `fix_firewall.ps1`을 **관리자 PowerShell**로 실행 (3000 포트 인바운드 허용).
3. 폰이 같은 Wi-Fi에 있을 때만 접속된다. 이 구성이면 외부에 노출이 없어 가장 안전하다.

### 외부(어디서든) 쓰려면

지금 앱은 평문 HTTP + 토큰 방식이다. 인터넷에 그대로 열면 비밀번호와 토큰이 평문으로 오간다.
외부 사용이 필요하면 아래를 갖추고 여는 것이 원칙이다.

1. 도메인 연결 + 리버스 프록시로 HTTPS 종단 (Caddy가 가장 간단하다. 인증서 자동 발급)

   ```
   golf.example.com {
       reverse_proxy localhost:3000
   }
   ```

2. 앱 `mobile/services/AuthService.ts`의 `API_BASE`를 `https://golf.example.com`으로 바꾸고 앱을 다시 빌드.
3. 방화벽에서는 프록시 포트(443)만 열고 3000은 외부에 직접 열지 않는다.

## 5. DB 위치와 정체

- 실데이터는 전부 SQLite 파일 하나, `backend/prisma/dev.db`에 있다 (회원, 일정·조편성, 라운드·스코어, 모임 정보).
- 코드 업데이트를 해도 이 파일은 건드려지지 않는다. 테이블 구조 변경은 `npx prisma migrate deploy`가 맡는다.
- 이 파일에는 회원 이름·전화번호가 들어간다. **Git 커밋 금지** (.gitignore에 `*.db` 적용돼 있음), 백업 파일도 같은 수준으로 취급한다 (유지보수.md).

## 6. 세팅 완료 확인

```bash
curl https://내-주소/                    # 루트 응답
curl https://내-주소/api/club/stats      # 회원 수·평균 핸디캡·스코어 건수가 나오면 정상
pm2 status                               # thegolfapp이 online
```

폰 앱에서 로그인 → 회원 목록 조회 → 회원 1명 등록 → 서버 재시작(`pm2 restart thegolfapp`) → 다시 조회해서 남아 있으면 세팅 끝이다.
