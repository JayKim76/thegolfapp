# thegolfapp 서버 세팅 (Supabase + Vercel)

운영 구조는 와일드웨스트 ERP와 같은 방식이다. 자체 서버를 두지 않는다.

```
웹 관리자 콘솔 (Vercel 프로젝트: thegolfapp-web, Vite 정적 빌드)
휴대폰 앱 (API_BASE를 아래 API 주소로 바꾼 빌드)
        │  HTTPS
        ▼
API (Vercel 프로젝트: thegolfapp-api, backend/ 폴더, 서버리스 함수)
        │  Prisma
        ▼
Supabase PostgreSQL (회원·일정·라운드·스코어 전부)
```

## 1. Supabase 프로젝트 만들기 (사용자가 직접, 1회)

1. supabase.com에서 새 프로젝트 생성. **리전은 서울(ap-northeast-2) 권장** — 와일드웨스트 때처럼 싱가포르로 만들면 한국에서 느리다.
2. 프로젝트 비밀번호(DB password)를 정하고 안전한 곳에 보관한다. 이 비밀번호가 연결 문자열에 들어간다.
3. 대시보드 Database → Connection string에서 두 가지를 확인한다.
   - **Transaction pooler** (포트 6543) → API 실행용 `DATABASE_URL` (끝에 `?pgbouncer=true`)
   - **Session pooler** (포트 5432) → 마이그레이션/시드용 `DIRECT_URL`
   
   와일드웨스트에서 확인된 대로, Vercel 함수는 직접 연결(db.<ref>:5432)에 닿지 못한다. 반드시 풀러를 쓴다.

## 2. DB에 테이블 만들기 + 초기 데이터 (어시스턴트가 연결 문자열을 받아 실행)

```bash
cd backend
# .env에 DATABASE_URL(풀러 6543), DIRECT_URL(세션 풀러 5432)을 넣은 뒤
npx prisma migrate deploy   # init_postgres 마이그레이션으로 테이블 8개 생성
npm run seed                # 모임 1개 + 테스트 회원 30명 + 스코어 116건 + 코스 20개
```

주의: **seed는 전체 데이터를 지우고 다시 넣는다.** 초기 구축 때만 실행한다.

## 3. Vercel 프로젝트 2개

### 3-1. API 프로젝트 (thegolfapp-api)

- Root Directory: `backend`
- 환경변수 (Production):
  - `DATABASE_URL` = 트랜잭션 풀러(6543) + `?pgbouncer=true`
  - `DIRECT_URL` = 세션 풀러(5432)
  - `ADMIN_ID`, `ADMIN_PASSWORD`, `ADMIN_TOKEN` (기본값 사용 금지, 길고 랜덤하게)
  - `GEMINI_API_KEY` (OCR용)
- `backend/vercel.json`이 모든 경로를 `api/index.ts`(Express 앱)로 보내고, 빌드 때 `prisma generate`가 돈다 (vercel-build 스크립트).
- 함수 리전: DB가 서울이면 **icn1(서울)** 로 맞춘다 (프로젝트 Settings → Functions).

### 3-2. 웹 프로젝트 (thegolfapp-web)

- Root Directory: 레포 루트 (Vite 앱)
- 환경변수 (Production): `VITE_API_BASE` = `https://thegolfapp-api.vercel.app` (API 프로젝트 주소)
- 빌드 결과는 정적 파일이라 서버 비용이 없다. `VITE_API_BASE`는 빌드에 구워지므로, 바꾸면 재배포가 필요하다.

### 3-3. 휴대폰 앱

`mobile/services/AuthService.ts`의 `API_BASE`를 `https://thegolfapp-api.vercel.app`으로 바꾸고 다시 빌드한다 (EAS preview). 그 뒤로는 집 PC 서버가 필요 없다.

## 4. 환경변수 전체 목록 (백엔드)

| 변수 | 필수 | 설명 |
|---|---|---|
| `DATABASE_URL` | 예 | Supabase 트랜잭션 풀러(6543, ?pgbouncer=true). 실행용 |
| `APP_DATABASE_URL` | Vercel 운영 시 | 위와 같은 풀러 주소 — Supabase 연동이 소유한 `DATABASE_URL`(직접 연결 값)은 API로 덮어쓸 수 없어, 코드가 이 키를 우선 적용해 우회한다 |
| `DIRECT_URL` | 예 | Supabase 세션 풀러(5432). 마이그레이션·시드용 |
| `PORT` | 아니오 | 로컬 실행용 (기본 3000). Vercel에서는 무시됨 |
| `ADMIN_ID` / `ADMIN_PASSWORD` / `ADMIN_TOKEN` | 실사용 시 필수 | 관리자 단일 계정. 기본값(1234/dev-admin-token) 사용 금지 |
| `GEMINI_API_KEY` | OCR용 | 서버(Vercel 환경변수)에만. 웹/앱에 넣지 않는다 |
| `GEMINI_OCR_MODEL` | 아니오 | 기본 gemini-2.5-flash |

로컬 PC에서 띄우는 예전 방식(pm2/systemd, SQLite)도 코드는 남아 있지만, DB가 PostgreSQL로 바뀌었으므로 로컬 실행 시에도 Postgres가 필요하다. 관련 파일: `backend/ecosystem.config.js`, `deploy/thegolfapp.service`. 운영 기준은 이 문서의 Supabase+Vercel 구성이다.

## 5. 세팅 완료 확인

```bash
curl https://thegolfapp-api.vercel.app/                 # "The Golf App Backend is running!"
curl https://thegolfapp-api.vercel.app/api/club/stats   # 회원 30명, 스코어 116건이 나오면 정상
```

웹 주소에서 관리자 로그인 → 대시보드에 실제 숫자가 보이고, 회원 1명을 등록한 뒤 새로고침해도 남아 있으면 끝이다.
