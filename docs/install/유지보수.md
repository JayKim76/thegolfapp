# thegolfapp 유지보수

운영이 시작된 뒤에 필요한 것만 모았다. 핵심은 하나다. **실데이터는 `backend/prisma/dev.db` 파일 하나에 전부 들어 있다.** 이 파일을 지키는 것이 유지보수의 절반이다.

## 1. 백업

### 수동 백업 (스크립트)

레포에 스크립트가 들어 있다. 서버를 멈추지 않고 SQLite 공식 백업 방식으로 복사한다 (sqlite3 CLI가 없으면 파일 복사로 대체하고, 그 경우 트래픽이 없는 시간에 실행 권장).

```bash
# Linux/macOS
backend/scripts/backup-db.sh
# Windows PowerShell
powershell -File backend\scripts\backup-db.ps1
```

- 결과: `backend/backups/dev-YYYYMMDD-HHMMSS.db` 형태로 쌓이고, 최근 14개만 남기고 지운다.
- 백업 파일에도 회원 이름·전화번호가 들어 있다. 외부 공유 금지, Git 커밋 금지 (*.db는 .gitignore 처리됨).

### 자동 백업

- Linux: cron에 하루 1회 등록 — `0 3 * * * cd /opt/thegolfapp/backend && ./scripts/backup-db.sh`
- Windows: 작업 스케줄러에 같은 스크립트를 하루 1회로 등록.

### 복원

```bash
pm2 stop thegolfapp           # 또는 systemctl stop thegolfapp
cp backups/dev-20261029-030000.db prisma/dev.db
pm2 start thegolfapp
curl localhost:3000/api/club/stats    # 숫자 확인
```

복원 전에 현재 dev.db도 한 번 백업해 두는 것이 안전하다.

## 2. 업데이트 절차

코드만 바뀔 때와 DB 구조까지 바뀔 때가 같은 절차다. 순서:

```bash
cd thegolfapp
git pull
cd backend
npm install
npx prisma migrate deploy     # 테이블 구조 변경이 있으면 여기서 적용됨
npm run build
pm2 restart thegolfapp        # 또는 systemctl restart thegolfapp
curl localhost:3000/api/club/stats    # 확인
```

- **주의: `npm run seed`는 업데이트 절차에 없다.** seed는 전체 데이터를 지우고 테스트 데이터로 덮는다. 운영 DB에 실행하면 복원 외에는 되돌릴 수 없다.
- 앱(모바일)을 고쳤으면 폰 쪽도 다시 빌드해 배포한다 (설치-가이드 2번). 특히 서버 주소를 바꿨으면 앱 재빌드가 필수다.
- 업데이트 전 백업 1회가 원칙이다.

## 3. 계정·키 교체

전부 `backend/.env`를 고치고 서버를 재시작하면 된다 (`pm2 restart thegolfapp`).

| 대상 | 절차 | 영향 |
|---|---|---|
| 관리자 비밀번호 | `ADMIN_PASSWORD` 변경 → 재시작 | 앱에서 새 비밀번호로 로그인 |
| 관리자 토큰 | `ADMIN_TOKEN` 변경 → 재시작 | 로그인돼 있던 앱은 전부 로그아웃 상태가 됨 (쓰기 401). 재로그인하면 됨 |
| Gemini 키 | `GEMINI_API_KEY` 변경 → 재시작 | OCR만 영향. 키 없이도 나머지는 동작 |
| 관리자 ID | `ADMIN_ID` 변경 → 재시작 | - |

비밀번호·토큰은 길고 랜덤하게 만든다. 메모장이나 코드에 적어두지 않는다.

## 4. 일상 점검

| 주기 | 볼 것 |
|---|---|
| 주 1회 | `pm2 status`가 online인지, `curl /api/club/stats` 응답, 서버 디스크 여유 |
| 월 1회 | 백업 파일이 쌓이고 있는지, 그중 1개를 임시로 복원해 열리는지 |
| 분기 1회 | 관리자 비밀번호·토큰 교체, 안 쓰는 회원 정리(앱의 회원 관리에서 삭제) |

로그는 `pm2 logs thegolfapp` (최근 로그와 에러). systemd면 `journalctl -u thegolfapp -n 100`.

## 5. 장애 대응

| 증상 | 확인할 것 (순서대로) |
|---|---|
| 앱이 서버에 못 붙음 | ① 서버 실행 중인가 (`pm2 status`) ② 폰과 서버가 같은 네트워크인가 ③ 서버 IP가 바뀌지 않았나 ④ 방화벽 3000 (Windows는 fix_firewall.ps1) ⑤ 앱의 `API_BASE` 주소가 서버와 같은가 |
| 로그인이 안 됨 | `.env`의 `ADMIN_ID`/`ADMIN_PASSWORD` 값. 바꾼 적 있으면 서버 재시작을 했는지 |
| 저장이 401로 실패 | 토큰이 바뀐 뒤 재로그인 안 한 상태일 수 있다. 로그아웃 후 다시 로그인. 그래도면 `ADMIN_TOKEN`이 서버 .env와 앱이 받은 값과 같은지 (재시작 여부) |
| OCR이 "GEMINI_API_KEY가 설정되지 않았습니다" | 서버 `.env`에 키를 넣고 재시작했는지. 키는 앱이 아니라 서버에 넣는 것이다 |
| OCR이 "선수를 읽지 못했습니다"(422) | 사진 문제다. 카드 전체가 나오게, 빛 반사 없이 다시 촬영. 인식은 초안이라 확인 화면에서 고치는 게 정상 흐름 |
| 서버가 안 뜸 (포트 충돌) | `EADDRINUSE`면 3000을 다른 프로세스가 쓰는 중. `PORT`를 바꾸거나 그 프로세스를 종료 |
| 마이그레이션 실패 | 대부분 DB 파일 권한 또는 서버가 DB를 잡고 있는 경우. 서버를 멈추고 `npx prisma migrate deploy` 후 다시 시작 |
| 데이터가 이상함 | 앱에서 지울 수 있는 건 앱으로 (회원 삭제, 라운드 삭제). 그 외에는 백업 복원이 정석. DB 파일을 직접 고치는 것은 마지막 수단 |

## 6. 데이터 관리 메모

- 회원 삭제: 앱 회원 관리에서 삭제하면 그 회원의 라운드 기록도 함께 삭제된다 (DB cascade). 지우기 전 확인.
- 라운드 삭제: `DELETE /api/rounds/:id` (관리자 토큰 필요). 앱의 기록 화면에는 아직 삭제 버튼이 없어서, 잘못 입력한 라운드는 당분간 이 API나 다음 앱 업데이트로 지운다.
- 테스트 회원 30명(테스트회원XX)은 시드 데이터다. 실제 운영을 시작할 때 앱에서 지우고 실제 회원을 등록하면 된다.
