# thegolfapp 유지보수

운영이 시작된 뒤에 필요한 것만 모았다. 실데이터는 **Supabase PostgreSQL**에 있다. 예전 SQLite 시절 자료(파일 백업 스크립트 등)는 로컬 개발용으로만 남아 있다.

## 1. 백업

### 운영 DB (Supabase)

- Supabase가 자동 백업을 제공한다 (무료 플랜은 일 단위 백업 보존 기간이 짧다). 대시보드 Database → Backups에서 확인한다.
- 중요한 변경 전에는 수동 덤프를 한 번 떠 두는 것이 안전하다.

```bash
pg_dump "<DIRECT_URL 세션 풀러 주소>" -f thegolfapp-backup-$(date +%F).sql
```

- 덤프 파일에도 회원 이름·전화번호가 들어 있다. 외부 공유 금지, Git 커밋 금지.

### 복원

Supabase 대시보드 백업 복원이 1순위다. 덤프로 복원할 때는 새 프로젝트/스키마에 `psql "<주소>" -f 파일.sql` 순서로 넣고, 복원 뒤 `curl https://thegolfapp-api.vercel.app/api/club/stats`로 숫자를 확인한다.

### (구) 로컬 SQLite 백업 스크립트

`backend/scripts/backup-db.sh` / `.ps1`은 SQLite 시절 로컬 개발용이다. 운영(Supabase)에는 쓰지 않는다.

## 2. 업데이트 절차

코드만 바뀔 때와 DB 구조까지 바뀔 때가 같은 절차다. 순서:

```bash
cd thegolfapp
git pull
cd backend
npm install
# .env의 DIRECT_URL(세션 풀러)로 운영 DB에 먼저 적용
npx prisma migrate deploy
# 이후 GitHub 연동 또는 재배포로 Vercel에 반영하고 확인
curl https://thegolfapp-api.vercel.app/api/club/stats
```

로컬 자체 서버(pm2) 운영이면 여기에 `npm run build && pm2 restart thegolfapp`가 붙는다.

- **주의: `npm run seed`는 업데이트 절차에 없다.** seed는 전체 데이터를 지우고 테스트 데이터로 덮는다. 운영 DB에 실행하면 복원 외에는 되돌릴 수 없다.
- 앱(모바일)을 고쳤으면 폰 쪽도 다시 빌드해 배포한다 (설치-가이드 2번). 특히 서버 주소를 바꿨으면 앱 재빌드가 필수다.
- 업데이트 전 백업 1회가 원칙이다.

## 3. 계정·키 교체

전부 값을 고치고 다시 적용하면 된다. 운영은 **Vercel 프로젝트(thegolfapp-api) 환경변수**를 고친 뒤 재배포, 로컬은 `backend/.env`를 고치고 재시작.

| 대상 | 절차 | 영향 |
|---|---|---|
| 관리자 비밀번호 | `ADMIN_PASSWORD` 변경 → 재시작 | 앱에서 새 비밀번호로 로그인 |
| 관리자 토큰 | `ADMIN_TOKEN` 변경 → 재시작 | 로그인돼 있던 앱은 전부 로그아웃 상태가 됨 (쓰기 401). 재로그인하면 됨 |
| Gemini 키 | `GEMINI_API_KEY` 변경 → 재시작 | OCR만 영향. 키 없이도 나머지는 동작 |
| 관리자 ID | `ADMIN_ID` 변경 → 재시작 | - |

비밀번호·토큰은 길고 랜덤하게 만든다. 메모장이나 코드에 적어두지 않는다.

## 4. 일상 점검

| 주기 | 볼 것 |
|---|---|
| 주 1회 | `curl https://thegolfapp-api.vercel.app/api/club/stats` 응답, Vercel 배포 상태, Supabase 사용량 |
| 월 1회 | 백업 파일이 쌓이고 있는지, 그중 1개를 임시로 복원해 열리는지 |
| 분기 1회 | 관리자 비밀번호·토큰 교체, 안 쓰는 회원 정리(앱의 회원 관리에서 삭제) |

로그는 Vercel 대시보드의 Runtime Logs에서 본다. 로컬 운영이면 `pm2 logs thegolfapp`.

## 5. 장애 대응

| 증상 | 확인할 것 (순서대로) |
|---|---|
| 앱/웹이 서버에 못 붙음 | ① API 주소가 응답하는가 (`curl https://thegolfapp-api.vercel.app/`) ② 앱의 `API_BASE`·웹의 `VITE_API_BASE`가 그 주소와 같은가 ③ Vercel 배포가 실패하지 않았나 (대시보드 확인) |
| 로그인이 안 됨 | `.env`의 `ADMIN_ID`/`ADMIN_PASSWORD` 값. 바꾼 적 있으면 서버 재시작을 했는지 |
| 저장이 401로 실패 | 토큰이 바뀐 뒤 재로그인 안 한 상태일 수 있다. 로그아웃 후 다시 로그인. 그래도면 `ADMIN_TOKEN`이 서버 .env와 앱이 받은 값과 같은지 (재시작 여부) |
| OCR이 "GEMINI_API_KEY가 설정되지 않았습니다" | 서버 `.env`에 키를 넣고 재시작했는지. 키는 앱이 아니라 서버에 넣는 것이다 |
| OCR이 "선수를 읽지 못했습니다"(422) | 사진 문제다. 카드 전체가 나오게, 빛 반사 없이 다시 촬영. 인식은 초안이라 확인 화면에서 고치는 게 정상 흐름 |
| API가 500을 냄 | Vercel Runtime Logs 확인. 대부분 `DATABASE_URL`이 직접 연결로 돼 있거나 풀러가 아닌 경우다 (서버-세팅.md 1번). 환경변수를 바꾼 뒤에는 재배포해야 적용됨 |
| 마이그레이션 실패 | 대부분 DB 파일 권한 또는 서버가 DB를 잡고 있는 경우. 서버를 멈추고 `npx prisma migrate deploy` 후 다시 시작 |
| 데이터가 이상함 | 앱에서 지울 수 있는 건 앱으로 (회원 삭제, 라운드 삭제). 그 외에는 백업 복원이 정석. DB 파일을 직접 고치는 것은 마지막 수단 |

## 6. 데이터 관리 메모

- 회원 삭제: 앱 회원 관리에서 삭제하면 그 회원의 라운드 기록도 함께 삭제된다 (DB cascade). 지우기 전 확인.
- 라운드 삭제: `DELETE /api/rounds/:id` (관리자 토큰 필요). 앱의 기록 화면에는 아직 삭제 버튼이 없어서, 잘못 입력한 라운드는 당분간 이 API나 다음 앱 업데이트로 지운다.
- 테스트 회원 30명(테스트회원XX)은 시드 데이터다. 실제 운영을 시작할 때 앱에서 지우고 실제 회원을 등록하면 된다.
